# Evidence

Evidence anchors are stable references for the scorecard and handoff.

## E1 - Standard inherited presentation

The site uses Docusaurus' classic preset and one autogenerated sidebar; the repository owns no custom visual layer (`docs/docusaurus.config.ts:24-50`, `docs/sidebar.ts:8-10`). The presentation is inherited from a mutable `ghcr.io/the-running-dev/docs-template:latest` image (`docs/Dockerfile:1-16`). The deployed layout is the conventional fixed top navigation, left sidebar, article, and right table of contents.

## E2 - Primary task and onboarding order

The Getting Started page contains requirements, installation, dependency-injection registration, a first call, and error handling (`docs/docs/getting-started.md:9-109`). However, its first installation command is `dotnet add package SubZeroDev.WinGet` (`docs/docs/getting-started.md:15-19`), before the GitHub Packages source and authentication instructions (`docs/docs/getting-started.md:21-32`). A live check on 2026-08-14 found no NuGet.org flat-container entry for `SubZeroDev.WinGet` (HTTP 404), so this first step does not currently support an unconfigured first-time user.

The homepage does not designate one primary action. Getting Started is presented as one peer sidebar link and one generic `Read` label in a ten-topic table (`docs/docs/index.md:133-148`).

## E5 - Copy, clarity, and behavior mismatches

The content discloses significant limitations and friction: GitHub Packages authentication (`docs/docs/getting-started.md:30-32`), ARM64 hardware validation status and the pending x64 packed-consumer smoke test (`docs/docs/getting-started.md:11-13,44`), the project-reference exception (`docs/docs/getting-started.md:46-50`), and the deliberate CLI-backed exceptions (`docs/docs/index.md:25`). No forced continuity, hidden cost, fake scarcity, confirmshaming, or coercive opt-in was found.

Clarity and honesty defects remain:

- The `GitHub` column links to hosted-site routes rather than GitHub, and the preceding `docs/` link also points to the site (`docs/docs/index.md:135-148`).
- The Introduction site link targets `/`, which redirects to the homepage rather than `/docs/intro` (`docs/docs/index.md:139`, `docs/static/index.html:15-19`).
- `Usage` behaves as both a disclosure and a navigation link to the same destination as its first child (`docs/docs/usage/_category_.json:2-4`).
- Ten repeated links are labeled only `Read` (`docs/docs/index.md:139-148`).
- Unexplained or unnecessarily internal first-use terms include COM, public surface, WinMD, transitive build target, IL-only AnyCPU, and HRESULT (`docs/docs/index.md:10-12,86-94`; `docs/docs/getting-started.md:34,44,109`).
- Absolute or qualitative claims include `full option control`, `every public API`, `safely`, `full surface`, and `actionable message` (`docs/docs/index.md:19,71,80`; `docs/docs/getting-started.md:54,96`).

## E6 - Chrome, attention, and failure residue

The restrained white/gray chrome generally recedes behind content and no modal or idle animation was observed. Nevertheless, the homepage combines onboarding with maintainer build/release information, documentation-system internals, specification, roadmap, and license (`docs/docs/index.md:107-160`).

The deployed homepage also visibly renders `An error occurred: giscus is not installed on this repository` after the article. It is ordinary content rather than an announced alert. The inherited wrapper defaults comments to enabled when front matter omits `comments`; the audited local pages do not opt out.

## E8 - Weight and friction

Measured against the deployed homepage:

- Initial observed JavaScript transfer: 794,156 compressed bytes across 21 JS assets; 761,333 bytes belonged to 11 executed/initial script assets and 32,823 bytes to ten link-only prefetch chunks.
- Main bundle alone: 722,389 gzip-transfer bytes; runtime: 2,167 bytes.
- Primary-view requests: 28 top-level observed requests including HTML. Getting Started: 26.
- Functional-readiness proxy: median 750 ms over three cache-busted navigations (741, 971, 750 ms), measured until the theme control was visible and verified interactive. This is not Lighthouse TTI.
- Idle animation count: 0 observed.
- Initial notification/badge/modal count: 1 total (0 active notifications, 1 build badge, 0 modals).
- Dark-mode control works and changes `data-theme`.
- The deployed CSS contains `@media (prefers-reduced-motion:reduce)` that zeroes Docusaurus transition variables.
- Two cross-origin portfolio JSON requests and a Giscus iframe are loaded despite not supporting the primary onboarding task.

Request count may be a lower bound because nested iframe resources can be omitted from the top-level inventory. Transfer sizes are gzip bytes. The readiness number is a functional proxy without simulated cold-network throttling.

## E9 - Long-lasting qualities

The typographic hierarchy, neutral palette, and conventional documentation layout avoid obvious fad markers. The product name and core technical boundary are clear (`docs/docusaurus.config.ts:13,39`, `docs/docs/index.md:10-25`). However, inheriting presentation from an unpinned `:latest` image allows the visible design to drift independently of this repository (`docs/Dockerfile:1-16`).
