# FC24/FC25 observation harness

Scripts implementing [`../fc24-fc25-observation-plan.md`](../fc24-fc25-observation-plan.md).
Read that document first — it names what these two questions are, why a minimal harness
answers them without building the production deployment, and what a positive or
negative outcome licenses. This README is only the run order.

**This is not a slice and materialises nothing in `20-contract.md`.** No output here is
evidence in `design/10-design.md`'s sense except the dated records under
`design/self-hosted-source/observations/`, which `New-ObservationRecord.ps1` writes.
Everything under `harness/output/` is throwaway run state — gitignored, regenerated by
these scripts, and safe to delete between runs.

## Prerequisites

- An Entra tenant the maintainer administers (the plan's "Shared prerequisites").
- PowerShell 7+, the `Microsoft.Graph.Applications` and `Microsoft.Graph.Authentication`
  modules, and the `winget` client.
- For FC24: Windows Sandbox available (Windows 11 Pro/Enterprise/Education,
  virtualization enabled).
- An elevated PowerShell session if serving HTTPS (`Start-InformationEndpoint.ps1
  -UseHttps`) — it binds a certificate with `netsh` and may reserve a URL ACL.

## Quick path

**`Initialize-ObservationHarness.ps1`** runs steps 1-3 below in one elevated command:
app registration, endpoint (its own process), certificate trust, hosts entry, and
source registration. Add `-RunSearch` to also fire the triggering `winget search` for
FC25, or `-LaunchSandbox` to generate and launch the FC24 Sandbox automatically. The
WAM consent prompt itself is never automated - that is the observation, not setup toil.

```powershell
./Initialize-ObservationHarness.ps1 -RunSearch      # FC25
./Initialize-ObservationHarness.ps1 -LaunchSandbox  # FC24 (run at least twice - see step 5 below)
./Initialize-ObservationHarness.ps1 -Remove -Force  # tear down everything it created
```

Then record the outcome with `New-ObservationRecord.ps1` (step 6 below) as usual. The
rest of this section documents the individual steps it wires together - read it if the
quick path fails partway, or to run a step in isolation.

## Run order

1. **`New-EntraObservationApp.ps1`** — creates the throwaway app registration exposing a
   custom resource/scope. Writes `output/entra-app.json`. Leave
   `-PreAuthorizeWinGetClient` off for the first run; the plan's FC25 step 5/6 wants to
   see the actual consent prompt and whatever tenant step it requires before assuming
   pre-authorization is that step.

2. **`Start-InformationEndpoint.ps1 -UseHttps`** (elevated, its own window) — serves
   `/information` advertising that resource/scope with `Cache-Control: no-store`, and a
   `/manifestSearch` stub that logs whether a bearer token arrived. Leave this running;
   it stops itself after 30 idle minutes or on Ctrl+C. It prints the LAN address to give
   FC24's Sandbox instance.

3. **`Register-ObservationSource.ps1 -Arg https://winget-observation.local:8443`** —
   registers the source, `Explicit`, on this machine.

4. **FC25, interactively, from a session with no cached WAM account for the fixed
   client id:**

   ```powershell
   winget search test --source FC24FC25Observation
   ```

   Watch the consent step. Sign in and consent, or observe the tenant's refusal — both
   are named outcomes in the plan. If consent needed a specific tenant step, note it for
   the record.

5. **`New-SandboxHarness.ps1 -HostAddress <the address step 2 printed>`** (only once
   FC25 is positive — FC24 presupposes it, per the plan) — exports the certificate's
   public half, writes a bootstrap script, and writes a `.wsb` file. Launch the `.wsb`
   (double-click, or `Start-Process`) to get a fresh, non-Entra-joined Sandbox instance
   that trusts the certificate, registers the same source, and runs the same search
   automatically at logon — watch for the WAM window inside the Sandbox.

   **Repeat this from at least two separate fresh instances** before treating either
   outcome as settled (the plan's step 6) — re-launch the same `.wsb` again rather than
   reusing a running instance.

6. **`New-ObservationRecord.ps1`** — writes the dated record under
   `design/self-hosted-source/observations/`, once per question, from what steps 4 and
   5 actually showed (the Sandbox run's log is at
   `output/sandbox-share/fc24-run.log`). This script does not decide the outcome or
   adjudicate a negative one — that is the maintainer's, per the plan.

## Cleanup

None of this is meant to persist once both observations are recorded.

```powershell
./New-EntraObservationApp.ps1 -Remove -Force
./Register-ObservationSource.ps1 -Remove
```

Also remove the self-signed certificate `Start-InformationEndpoint.ps1 -UseHttps`
created (`Cert:\LocalMachine\My`, subject `winget-observation.local`, thumbprint
printed at creation) if this harness will not run again, and delete `output/` if you
want the LAN address and logs gone too — nothing under it is referenced from anywhere
else.

## What this harness deliberately does not do

Named in the plan's "Why a minimal harness" section, restated here only as a checklist:
no manifest tree, no artifact store, no offsite backup, no production certificate, and
`/manifestSearch` never returns real results — it exists only to observe whether a
bearer token arrived. Do not extend this harness to answer FC6, FC13, FC19, or FC20;
each needs the production deployment this is deliberately not building yet.
